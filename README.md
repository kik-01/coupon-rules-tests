# 陶瓷商城优惠券规则 · 测试设计与缺陷挖掘

一个**算价逻辑**的测试设计项目：判定表 + 边界值 + 属性测试 + 需求逐条对照，22 条用例通过，抓出 4 个金额计算缺陷。

> 被测对象是纯函数的算价引擎（`app/coupon_engine.py`），不是页面。
> 算价这类逻辑就该在单元/接口层测掉——等它上了页面再点，一个组合要操作七八步，没人测得完。

---

## 一、这个项目解决什么问题

大多数「功能测试项目」是这样写的：打开登录页，输入错误密码，验证提示文案。
问题在于：这类用例证明不了设计能力，只是把页面点了一遍。

这个项目不点页面，只干一件事：**证明算价逻辑在哪些组合下会算错**。

| 常规做法 | 这个项目 |
|---|---|
| 照着页面点，想到哪测到哪 | 先拆规则，画判定表，14 条覆盖主要组合 |
| 只测正常流程 | 门槛差 1 分、包邮临界、折扣取整方向都单独测 |
| 人工能想到的才测 | 随机造 1000 笔订单撞不变量，撞出人工想不到的 |
| 需求没写清就按自己理解测 | 列出 7 条歧义，写明假设与影响，等产品确认 |

## 二、成果

- **28 条用例**：22 通过，6 条标记为已知缺陷（`xfail(strict=True)`）
- **4 个缺陷**：3 个 P1、1 个 P0，全部是金额算错，不是功能不能用
- 其中 **1 个是随机测试撞出来的**，靠读需求想不到；**1 个是拿需求逐条对代码对出来的**

| 缺陷 | 一句话 |
|---|---|
| BUG-001 | 品类券门槛用整单金额判断，其他品类能凑单 |
| BUG-002 | 满减门槛把运费算进去了 |
| BUG-003 | 优惠超过商品金额不截断，应付金额算成负数（可被刷） |
| BUG-004 | 同类券只能用一张，代码只限制了满减券，品类券能叠两张 |

详见 [03-缺陷记录.md](03-缺陷记录.md)

## 三、怎么跑

```bash
python -m pytest              # 22 passed, 6 xfailed
python -m pytest -rx          # 看 6 条 xfail 的原因
```

只依赖 PyYAML（读判定表数据），`pip install -r requirements.txt` 即可。
**判定表 14 条在 `data/coupon_cases.yaml`**：新增一个组合只加一段数据，不用碰测试代码；
加载时做整数校验（`tests/case_loader.py`），金额写成 `128.00` 或 `"12,800"` 会被挡下来并指出是哪条用例。
